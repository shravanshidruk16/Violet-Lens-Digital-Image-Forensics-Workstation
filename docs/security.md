# Evidence Handling, Security Architecture & Privacy Policy

## 1. Principles of Forensic Evidence Handling
In digital forensics, mishandling evidence can compromise chain of custody and render findings inadmissible. Violet Lens is engineered with defensive security and strict evidence preservation controls:

1. **Unaltered Byte Stream Ingestion**: Hashing (SHA-256) is executed directly on the in-memory byte buffer received from the client before any parsing, decoding, or re-encoding.
2. **Immutable Original Evidence**: Uploaded evidence bytes are never overwritten, transcoded, or modified in place.
3. **Decoupled Derived Previews**: All browser visual displays and ELA outputs are derived copies produced in separate memory buffers.
4. **Offline Local Execution**: The workstation operates entirely locally with zero external network calls, ensuring that sensitive evidence never leaves the analyst's machine.

## 2. Upload Restrictions & Resource Protection

### Upload Size Limit
Flask enforces a strict maximum content length:
```python
MAX_CONTENT_LENGTH = 15 * 1024 * 1024  # 15 Megabytes
```
Payloads exceeding 15 MB are rejected immediately with HTTP 413 (Payload Too Large) before consuming backend memory.

### Decompression Bomb Defense
Malicious actors can craft small images (e.g. 50 KB compressed) that expand to gigabytes of raster memory upon decompression, inducing Denial of Service (DoS). Violet Lens sets:
```python
Image.MAX_IMAGE_PIXELS = 50_000_000  # 50 Megapixel ceiling
```
Any image exceeding 50 million pixels is halted during the verification pass before allocation.

### File Format Verification
Violet Lens does not trust client-supplied MIME types or filename extensions:
- Binary magic bytes are inspected directly (`\xFF\xD8\xFF`, `\x89PNG`, `RIFF....WEBP`, `BM`, `II*\x00`).
- Pillow's `img.verify()` is executed on an isolated stream.
- Non-image binaries or disguised executables are rejected with structured 400 error codes.

## 3. Storage Architecture & Lifecycle Management

### Unpredictable Examination Identifiers
Examinations are assigned a cryptographically random UUIDv4:
```python
exam_id = str(uuid.uuid4())
```
All endpoints validate the examination ID against a strict regex pattern (`^[a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12}$`) before accessing filesystem resources, preventing directory traversal attacks (`../`).

### Temporary Storage & Expiration
- Examination records are stored in `instance/examinations/` (excluded from git).
- Records possess a configurable Time-To-Live (TTL):
  ```python
  EXAMINATION_TTL_SECONDS = 3600  # 1 hour
  ```
- Before each new examination request, a background cleanup routine scans and deletes `.json` and `.png` artifacts older than the TTL.

## 4. Privacy & Geolocation Protection

Digital images frequently embed sensitive GPS coordinates revealing the exact physical location where a photograph was captured.

- **Privacy-Shielding by Default**: If GPS metadata is parsed, coordinates are masked in the UI.
- **Controlled Local Disclosure**: Coordinates can only be revealed through explicit user interaction ("Reveal Coordinates Locally").
- **Zero Third-Party Telemetry**: GPS coordinates are never sent to external mapping APIs unless the analyst deliberately clicks the external map link.

## 5. Defensive HTTP Security Headers

Every HTTP response generated by Violet Lens includes defensive security headers:
- `X-Content-Type-Options: nosniff`: Prevents MIME-sniffing vulnerabilities.
- `X-Frame-Options: SAMEORIGIN`: Protects against clickjacking.
- `Referrer-Policy: strict-origin-when-cross-origin`: Minimizes referrer leakage.
- `X-XSS-Protection: 1; mode=block`: Guards legacy browsers against reflected XSS.
